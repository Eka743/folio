# Folio v0.2 capability matrix

This is the release decision for the browser-local public surface. A format is
listed as ready only when it produces a validated downloadable file in the
browser matrix. Detection or preview alone does not count as conversion.

| Conversion | Status | Evidence / boundary |
| --- | --- | --- |
| Merge PDF | Ready | Chromium, Firefox and WebKit; page-count and signature validation; same File object twice covered. |
| Split PDF | Ready | Chromium, Firefox and WebKit; selected page counts validated. |
| JPG/PNG → PDF | Ready | Chromium, Firefox and WebKit; generated PDF parsed and page counts validated. |
| DOCX → PDF | Beta | Realistic generated DOCX corpus covers formatting, list, table, image, hyperlink, Unicode and long-document pagination; review fidelity before sharing. |
| Multiple DOCX → one PDF | Beta | Each Word file is converted locally, validated as a PDF segment, then merged in selected order; complex layout and pagination remain renderer-dependent. |
| Mixed PDF/DOCX/Markdown/JPG/PNG → one PDF | Beta | Every source must convert successfully; source filenames are preserved in failures and the final page count is validated. |
| PDF → JPG | Ready | Chromium, Firefox and WebKit; JPEG signatures and browser decoding validated; ZIP contents validated for multi-page output. |
| Rotate PDF | Ready | Chromium, Firefox and WebKit; generated page counts and rotation output validated. |
| Compress PDF | Ready | Chromium, Firefox and WebKit; output parser validation and honest size reporting. |
| Markdown → PDF | Ready | Sanitized Markdown subset, safe local/data images, styled multi-page A4 output, PDF signature/parser validation. |
| PDF → Markdown | Beta | Local PDF.js text extraction with conservative headings/lists and link recovery; scanned and complex layouts are reported honestly. |
| Pages → PDF | Reject | Generic modern iWork rendering is not reliable browser-local. Embedded QuickLook PDF extraction is a preview action, not native conversion. |
| Keynote → PDF | Defer | No credible browser-local production path met the usefulness bar. |
| Numbers → PDF | Defer | No credible browser-local production path met the usefulness bar. |
| PPTX → PDF | Reject | No maintained browser-local path was available that could guarantee useful slide layout, text, images and ordering. |
| XLSX → PDF | Reject | No maintained browser-local path was available that could guarantee useful worksheet layout, sizing and pagination. |

## Universal Drop boundaries

Universal Drop accepts up to 20 documents and applies a 150 MB aggregate
client-side limit. Inspection and conversion are sequential so WebKit picker
handles do not compete for reads and intermediate buffers are not retained by
an unbounded worker pool. A batch action is shown only when every detected
input has a matching capability in the graph.

## Microsoft format investigation

The repository has no public PPTX or XLSX processing path. The local dependency
audit confirmed that the candidate JavaScript packages available in the
ecosystem are not equivalent to a PDF layout engine: `pptxgenjs` is a
presentation authoring package, while `xlsx` and `exceljs` expose workbook data
parsing/management rather than a faithful browser print-layout renderer. The
dormant alternatives in this repository require Microsoft desktop applications
or the native helper, which is outside the public browser product. Adding a
button without reliable slide/worksheet layout would therefore violate the
output contract, so both conversions remain rejected for v0.2.

## Markdown safety boundary

Raw HTML is escaped, executable URLs are not emitted, and remote image URLs are
omitted instead of fetched. Input is bounded to 10 MB and must be non-empty
valid UTF-8 text.

## PDF extraction boundary

PDF → Markdown is reconstruction rather than an inverse conversion. Folio
extracts text locally, preserves page separation, and only infers headings and
lists from defensible layout signals. It does not provide OCR, cloud fallback,
or guaranteed table/column reconstruction.
