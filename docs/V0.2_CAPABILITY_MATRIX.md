# Folio v0.2 capability matrix

This is the release decision for the browser-local public surface. A format is
listed as ready only when it produces a validated downloadable file in the
browser matrix. Detection or preview alone does not count as conversion.

| Conversion | Status | Evidence / boundary |
| --- | --- | --- |
| Merge PDF | Ready | Chromium, Firefox and WebKit; page-count and signature validation; same File object twice covered. |
| Split PDF | Ready | Chromium, Firefox and WebKit; selected page counts validated. |
| JPG/PNG → PDF | Ready | Chromium, Firefox and WebKit; generated PDF parsed and page counts validated. |
| DOCX → PDF | Beta | Realistic generated DOCX corpus covers formatting, list, table, image, hyperlink, Unicode and long-document pagination; review fidelity before sharing. |
| Pages → DOCX | Beta | Real DOCX package is written locally and reopened structurally; Pages 15.3.1 opened, saved and reopened a representative output, while Word-specific fidelity was not assessed. |
| PPTX → PDF | Beta | Bounded OOXML parser supports multiple slides, text, tables, embedded PNG/JPEG and basic shapes; output signature, parser and slide count are validated. |
| Keynote → PPTX | Experimental | Real OOXML PPTX package is written and reopened through the safe parser; Keynote 15.3.1 opened, saved and reopened a representative two-slide output, while advanced Apple features remain out of scope. |
| XLSX → PDF | Beta | Bounded OOXML parser preserves multiple sheets, saved values/formulas, merged cells, dimensions and basic formatting; output is parsed and page-count validated. |
| Multiple DOCX → one PDF | Beta | Each Word file is converted locally, validated as a PDF segment, then merged in selected order; complex layout and pagination remain renderer-dependent. |
| Mixed PDF/DOCX/Markdown/JPG/PNG → one PDF | Beta | Every source must convert successfully; source filenames are preserved in failures and the final page count is validated. |
| PDF → JPG | Ready | Chromium, Firefox and WebKit; JPEG signatures and browser decoding validated; ZIP contents validated for multi-page output. |
| Rotate PDF | Ready | Chromium, Firefox and WebKit; generated page counts and rotation output validated. |
| Compress PDF | Ready | Chromium, Firefox and WebKit; output parser validation and honest size reporting. |
| Markdown → PDF | Ready | Sanitized Markdown subset, safe local/data images, styled multi-page A4 output, PDF signature/parser validation. |
| PDF → Markdown | Beta | Local PDF.js text extraction with conservative headings/lists and link recovery; scanned and complex layouts are reported honestly. |
| Pages → PDF | Beta | Pinned iWork parser runs locally in a lazy Worker; Folio exports only its validated structured subset and fails closed for limited or unsupported content. |
| Keynote → PDF | Beta | Pinned iWork parser runs locally in a lazy Worker; supported slide content is rendered to a reviewable PDF and unsupported content fails closed. |
| Numbers → XLSX | Beta | Saved Numbers tables and values are exported to a validated XLSX locally; formulas are not recalculated and unsupported formatting is not represented. |
| Numbers → PDF | Beta | Saved Numbers tables and chart data are rendered to a validated readable PDF locally; native print styling is not reproduced. |
| Embedded Apple PDF preview | Preview | A QuickLook `quicklook/preview.pdf` is offered as `Export embedded PDF preview`; it is not native conversion or editable output. |

## Primary 12-path fidelity fixture matrix

These marks describe the supported fixture subset, not pixel-perfect native-app
equivalence. `PASS` means the feature is represented and covered by a local
package/parser or output test; `PARTIAL` means the workflow is intentionally
bounded; `FAIL` means the path is rejected and not exposed as a public action.

| Path | Status | Text | Images | Tables | Layout | Structure |
| --- | --- | --- | --- | --- | --- | --- |
| DOCX → PDF | Beta | PASS | PASS | PASS | PARTIAL | PASS |
| DOCX → Pages | Reject | N/A | N/A | N/A | N/A | FAIL |
| PPTX → PDF | Beta | PASS | PASS | PASS | PARTIAL | PASS |
| PPTX → Keynote | Reject | N/A | N/A | N/A | N/A | FAIL |
| XLSX → PDF | Beta | PASS | FAIL | PASS | PARTIAL | PASS |
| XLSX → Numbers | Reject | N/A | N/A | N/A | N/A | FAIL |
| Pages → PDF | Beta | PASS | PASS | PARTIAL | PARTIAL | PARTIAL |
| Pages → DOCX | Beta | PASS | PASS | PARTIAL | PARTIAL | PASS |
| Keynote → PDF | Beta | PASS | PASS | PARTIAL | PARTIAL | PARTIAL |
| Keynote → PPTX | Experimental | PASS | PASS | PARTIAL | PARTIAL | PASS |
| Numbers → PDF | Beta | PASS | PASS | PARTIAL | PARTIAL | PASS |
| Numbers → XLSX | Beta | PASS | FAIL | PASS | PARTIAL | PASS |

The three `Reject` paths are deliberately absent from the capability graph:
Folio does not pretend to write native Pages, Keynote, or Numbers packages.
Native opening and editability evidence for representative reverse outputs is
recorded in `docs/IWORK_NATIVE_OUTPUT_VALIDATION.md`; this does not promote the
bounded subset to full native-fidelity support.

## Universal Drop boundaries

Universal Drop accepts up to 20 documents and applies a 150 MB aggregate
client-side limit. Inspection and conversion are sequential so WebKit picker
handles do not compete for reads and intermediate buffers are not retained by
an unbounded worker pool. A batch action is shown only when every detected
input has a matching capability in the graph.

## Microsoft format boundary

PPTX and XLSX use a bounded, schema-limited local parser. It is intentionally
not a full Office rendering engine: unsupported graphics, macros, external
relationships and unsafe embedded content fail closed. The generated PDF is a
faithful structured reconstruction for the supported subset, not a promise of
pixel-identical PowerPoint or Excel print output.

## Markdown safety boundary

Raw HTML is escaped, executable URLs are not emitted, and remote image URLs are
omitted instead of fetched. Input is bounded to 10 MB and must be non-empty
valid UTF-8 text.

## PDF extraction boundary

PDF → Markdown is reconstruction rather than an inverse conversion. Folio
extracts text locally, preserves page separation, and only infers headings and
lists from defensible layout signals. It does not provide OCR, cloud fallback,
or guaranteed table/column reconstruction.
